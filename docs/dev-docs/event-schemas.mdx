# Event Schemas

This page defines the proposed JSON messages Max patches send to the relay server during a performance. The server validates an event and distributes it to every device in the active session. Clients schedule an event locally, so a timestamped event can begin at the same intended moment on every device.

## Status

The baseline schema below is the initial implementation target. It assumes every connected device receives every event.

:::info Stretch goals: zones and keyframes

Zone targeting and keyframed effects are documented as planned extensions, but **are not supported yet**. Max patches must not send `target` or `keyframes` fields until those features are implemented by the server and mobile client.

:::

## Event envelope

Every event has the following top-level shape:

```json
{
  "schemaVersion": "1.0",
  "eventId": "intro-haptic-001",
  "sequence": 42,
  "type": "haptic",
  "timestamp": 1730000000000,
  "payload": {}
}
```

| Field | Type | Required | Description |
| --- | --- | --- | --- |
| `schemaVersion` | string | Yes | Schema version. The initial version is `"1.0"`. |
| `eventId` | string | Yes | A unique identifier for this event within the performance session. |
| `sequence` | integer | Yes | A monotonically increasing sequence number assigned by Max. It gives clients a deterministic order when two events affect the same output at the same time. |
| `type` | string | Yes | The event type listed in [Event types](#event-types). |
| `timestamp` | integer or `null` | Yes | Unix epoch time in milliseconds at which the client should execute the event. Use `null` for “as soon as received.” |
| `payload` | object | Yes | Properties specific to `type`. |

The event envelope does not include a session ID: the server determines the session from the authenticated Max connection and distributes the event only within that session.

## Timing and ordering

- Timestamped events should be sent sufficiently before their `timestamp` for the server to relay and clients to queue them. A `null` timestamp is appropriate for an immediate effect, but is not synchronized across devices.
- Clients execute each event independently. Multiple events with the same timestamp may therefore begin together—for example, a `haptic`, `screen`, and `caption` event.
- When two events control the same output at the same timestamp, the higher `sequence` value takes precedence. A newer haptic replaces a haptic already playing; a newer screen event replaces the current screen effect.
- Durations are expressed in milliseconds. A duration ends the event and restores the output to its state immediately before that event, unless a later event has already replaced it.

## Common value rules

| Value | Rule |
| --- | --- |
| Time and duration | Non-negative integer milliseconds. |
| `intensity` and `brightness` | Number from `0` through `1`, inclusive. These are normalized intent values; the mobile app maps them to device capabilities. |
| `color` | Six-digit sRGB hexadecimal string in the form `"#RRGGBB"`. |
| Asset alias | A non-empty string registered for the session and downloaded by the device during session join. |

## Event types

### `haptic`

Starts a continuous haptic response at a normalized intensity. The React Native client maps this intent to the native haptic implementation for the device.

```json
{
  "schemaVersion": "1.0",
  "eventId": "pulse-01",
  "sequence": 42,
  "type": "haptic",
  "timestamp": 1730000000000,
  "payload": {
    "intensity": 0.75,
    "sharpness": 0.4,
    "durationMs": 600
  }
}
```

| Payload field | Type | Required | Description |
| --- | --- | --- | --- |
| `intensity` | number | Yes | Normalized haptic strength. |
| `sharpness` | number | No | Normalized haptic character, from soft (`0`) to crisp (`1`). Clients without this capability may ignore it. |
| `durationMs` | integer | Yes | Length of the haptic response. |

### `torch`

Turns the device flashlight (rear-camera torch) on for a fixed interval. This does not capture camera video or images.

```json
{
  "schemaVersion": "1.0",
  "eventId": "torch-hit-01",
  "sequence": 43,
  "type": "torch",
  "timestamp": null,
  "payload": {
    "durationMs": 250
  }
}
```

| Payload field | Type | Required | Description |
| --- | --- | --- | --- |
| `durationMs` | integer | Yes | How long the torch remains on. |

The client must handle absent hardware or a denied camera permission gracefully.

### `screen`

Shows a full-screen solid color at a specified normalized brightness.

```json
{
  "schemaVersion": "1.0",
  "eventId": "blue-wash-01",
  "sequence": 44,
  "type": "screen",
  "timestamp": 1730000001200,
  "payload": {
    "color": "#0057FF",
    "brightness": 0.8,
    "durationMs": 1500
  }
}
```

| Payload field | Type | Required | Description |
| --- | --- | --- | --- |
| `color` | string | Yes | Full-screen color. |
| `brightness` | number | Yes | Normalized brightness/opacity for the color. |
| `durationMs` | integer | Yes | How long the screen effect remains visible. |

### `caption`

Displays text over the mobile app. An empty `text` string clears the current caption.

```json
{
  "schemaVersion": "1.0",
  "eventId": "caption-01",
  "sequence": 45,
  "type": "caption",
  "timestamp": 1730000001200,
  "payload": {
    "text": "Follow the lights",
    "durationMs": 3000
  }
}
```

| Payload field | Type | Required | Description |
| --- | --- | --- | --- |
| `text` | string | Yes | Caption content. Text formatting is owned by the mobile client. |
| `durationMs` | integer | No | How long to display the caption. When omitted, it remains until replaced or cleared. |

### `asset`

Displays a preloaded visual asset, such as a PNG or PDF. The client determines how to render an asset from its session manifest; Max sends only its alias.

```json
{
  "schemaVersion": "1.0",
  "eventId": "score-page-01",
  "sequence": 46,
  "type": "asset",
  "timestamp": 1730000005000,
  "payload": {
    "assetAlias": "score-page-1",
    "durationMs": 8000
  }
}
```

| Payload field | Type | Required | Description |
| --- | --- | --- | --- |
| `assetAlias` | string | Yes | Alias of a session-preloaded visual asset. |
| `durationMs` | integer | No | How long to display the asset. When omitted, it remains until replaced. |

### `audio`

Plays a preloaded audio asset. `startOffsetMs` and `durationMs` allow a Max patch to trigger a clip or a segment of a longer file.

```json
{
  "schemaVersion": "1.0",
  "eventId": "drone-clip-01",
  "sequence": 47,
  "type": "audio",
  "timestamp": 1730000005000,
  "payload": {
    "assetAlias": "low-drone",
    "startOffsetMs": 12000,
    "durationMs": 5000
  }
}
```

| Payload field | Type | Required | Description |
| --- | --- | --- | --- |
| `assetAlias` | string | Yes | Alias of a session-preloaded audio asset. |
| `startOffsetMs` | integer | No | Offset from the start of the asset. Defaults to `0`. |
| `durationMs` | integer | No | Clip length. When omitted, playback continues to the end of the asset. |

### `video`

Plays a preloaded video asset full-screen.

```json
{
  "schemaVersion": "1.0",
  "eventId": "video-clip-01",
  "sequence": 48,
  "type": "video",
  "timestamp": 1730000007000,
  "payload": {
    "assetAlias": "opening-loop",
    "startOffsetMs": 0,
    "durationMs": 10000
  }
}
```

| Payload field | Type | Required | Description |
| --- | --- | --- | --- |
| `assetAlias` | string | Yes | Alias of a session-preloaded video asset. |
| `startOffsetMs` | integer | No | Offset from the start of the video. Defaults to `0`. |
| `durationMs` | integer | No | Clip length. When omitted, playback continues to the end of the video. |

## Planned extension: zone targets

:::warning Not supported yet

All baseline events apply to the full session. The server must reject or ignore `target` until zone routing is implemented.

:::

The planned `target` field will let a Max patch send the same event type to a subset of the audience. It belongs beside `timestamp` in the event envelope:

```json
{
  "target": {
    "kind": "zone",
    "zoneId": "stage-left"
  }
}
```

`zoneId` values will be defined by the session configuration, not invented by individual Max patches. The implicit baseline target is the complete session.

## Planned extension: keyframes

:::warning Not supported yet

The initial client supports one value for the full duration of a `haptic` or `screen` event. It does not yet execute keyframe timelines.

:::

Keyframes will describe evolving effects such as a haptic ramp followed by pulses, or a color fade. A future event may add a `keyframes` array to its payload. Each frame is relative to the event timestamp.

```json
{
  "type": "haptic",
  "timestamp": 1730000010000,
  "payload": {
    "durationMs": 3000,
    "keyframes": [
      { "atMs": 0, "intensity": 0.0, "sharpness": 0.2 },
      { "atMs": 700, "intensity": 0.8, "sharpness": 0.4 },
      { "atMs": 1000, "intensity": 0.0 },
      { "atMs": 1200, "intensity": 1.0, "sharpness": 0.8 },
      { "atMs": 3000, "intensity": 0.0 }
    ]
  }
}
```

When implemented, `atMs` will be a non-negative offset inside `durationMs`. The client will linearly interpolate values between adjacent frames. Keyframes for a `screen` event will use `color` and `brightness`; keyframes for a `haptic` event will use `intensity` and optional `sharpness`.

## Validation expectations

The server should reject an event when its version or type is unknown, a required field is missing, a value falls outside its documented range, an asset alias is not registered for the session, or a timestamp/duration is invalid. It should return a structured error to the Max connection and never forward an invalid event to audience devices.
